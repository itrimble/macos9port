# Dashboard surface

Mode: Operate. The user pinned a professional dark technical dashboard, parity-first,
with Python backend and direct code implementation. These decisions take precedence
 over stylistic alternatives.

## Direction contract

THESIS: A development observatory that separates accepted behavior from implementation
and missing evidence. Reading a chart should expose the actual tasks behind it.

OWN-WORLD: Blue-black instrument panels, cool-white typography, cyan live-state light,
green acceptance, amber uncertainty, coral failure; fine ruled sections and accessible
status labels. Source and revision identifiers use tabular monospace.

STORY: See parity, identify the next blocking subsystem, open its evidence, then follow
the build that validates it. No decorative percentages or guessed benchmark values.

FIRST VIEWPORT: Fixed left navigation/checklist rail; a wide central parity ring with
component status bands and a latest-build strip. Below it a horizontal milestone wave
connects inventory to Finder/storage/browser/Quake and complete main. Primary action:
filter the checklist by clicking a component.

FORM: Instrument-panel observatory, candidate 4, seed 46ff2c70. Other grounded forms:
release train, test-lab notebook, filesystem navigator, observatory, kanban wall,
compatibility atlas, annotated dependency graph. The assigned fourth form fits the
user-pinned world. Barcode and poster-wall challengers lose product clarity; borrow
only their density discipline and progressive disclosure. Organic guide-map topology
loses clarity for exact build evidence; retain clear spatial grouping without shapes.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
